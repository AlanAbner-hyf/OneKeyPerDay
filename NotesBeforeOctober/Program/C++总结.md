## 1. C++ 的核心思想：对象、生命周期与 RAII【高频】

C++ 不只是“带类的 C”。它的核心能力是：

- **值语义**：对象可以像 `int` 一样复制、移动和组合。
- **零成本抽象**：模板、迭代器、RAII 等抽象原则上不为未使用的能力付费。
- **确定性生命周期**：自动对象离开作用域时立即析构，这是 RAII 的基础。
- **多范式**：同时支持过程式、面向对象、泛型和函数式风格。

### 1.1 存储期、作用域和生命周期

三者不要混淆：

- **作用域**决定名字在代码的哪里可见。
- **存储期**决定对象的存储存在多久，包括自动、静态、线程和动态存储期。
- **生命周期**是对象作为某种类型真正存在的时间，从初始化完成开始，到析构开始或存储被复用时结束。

常见对象：

| 对象                  | 典型存储位置                     | 生命周期                                 |
| --------------------- | -------------------------------- | ---------------------------------------- |
| 普通局部对象          | 通常在栈帧，也可能被优化到寄存器 | 进入作用域后构造，离开作用域析构         |
| 静态局部对象          | 静态存储区                       | 第一次执行到声明时初始化，程序结束时析构 |
| 全局/命名空间对象     | 静态存储区                       | 通常在`main` 前初始化，程序结束时析构  |
| `thread_local` 对象 | 每线程存储                       | 每个线程各有一份，随线程结束销毁         |
| `new` 创建的对象    | 自由存储区，通常由堆分配器支持   | 从构造完成到`delete`                   |

C++11 起，函数内静态局部变量的初始化由语言保证线程安全，常用于 Meyers Singleton；对象初始化之后的并发读写仍需自行同步。

### 1.2 RAII

RAII 是“构造时取得资源，析构时释放资源”。资源不仅是内存，还包括锁、文件、Socket 和数据库连接。

```cpp
void work() {
    std::lock_guard<std::mutex> lock(mutex); // 构造时加锁
    use_shared_data();
} // 正常返回或抛异常，lock 都会析构并解锁
```

RAII 把资源生命周期绑定到对象生命周期，避免每条返回路径都手工清理，是 C++ 异常安全的基础。优先使用标准容器、智能指针和资源包装类，尽量遵循 **Rule of Zero**：让成员自己管理资源，业务类无需手写析构、拷贝和移动函数。

### 1.3 未定义行为 UB

越界访问、使用悬空指针、错误的 `delete/delete[]`、有符号整数溢出、无同步数据竞争等都可能是未定义行为。UB 不只是“可能崩溃”，编译器可以假定它绝不发生并据此优化，所以程序可能表现出任何结果。

## 2. 内存模型、对齐与指针

### 2.1 进程内存布局

常见 ELF 进程映像可粗略理解为：

- `.text`：机器指令，通常可读、可执行。
- `.rodata`：字符串字面量等只读数据。
- `.data`：已显式初始化且初值非零的静态存储期对象。
- `.bss`：零初始化/未显式初始化的静态存储期对象；文件中通常只记录大小。
- 堆/自由存储区、内存映射区、每线程栈。

这只是典型实现，C++ 标准并不规定 ELF、堆栈方向或函数参数压栈顺序；后者由平台 ABI 和优化决定。

### 2.2 栈与堆

- 栈分配通常只是移动栈指针，快、局部性好，自动析构，但大小有限，深递归或大数组可能栈溢出。
- 堆适合运行期大小或跨作用域对象，分配较慢且可能碎片化，需要明确所有权。
- 同一进程的线程通常共享堆，每个线程有自己的调用栈；但指向栈对象的指针若被泄露给其他线程，对方技术上可能访问，因此“栈只能由本线程访问”不是语言保证。

### 2.3 内存对齐与类大小

对象地址要满足 `alignof(T)`。结构体成员按声明顺序放置，编译器可在成员之间和末尾插入 padding，使每个成员正确对齐，并让对象数组中的下一对象也对齐。

```cpp
struct A {
    char c;  // offset 0
    int  i;  // 常见 ABI 下 offset 4，中间填充 3 字节
    char d;  // offset 8，末尾可能再填充到 sizeof(A)==12
};
```

具体大小是实现相关的，应使用 `sizeof/alignof/offsetof` 验证。静态成员和普通成员函数不存放在每个对象中；虚函数通常使对象多一个虚表指针，但虚表、虚基表的精确布局属于 ABI 细节。空类大小至少为 1，以保证不同完整对象拥有不同地址；空基类优化或 `[[no_unique_address]]` 可能消除这部分开销。

不要用 `memcmp` 判断普通结构体的逻辑相等：padding 可能不同，成员也可能有非字节级的相等语义。应定义 `operator==`。

### 2.4 指针与引用

| 特性     | 指针                         | 引用                                     |
| -------- | ---------------------------- | ---------------------------------------- |
| 空状态   | 可为`nullptr`              | 必须绑定有效对象，语言层面没有正常空引用 |
| 改变目标 | 可以重新指向                 | 初始化后不能重新绑定                     |
| 使用     | 需解引用`*p`，支持指针运算 | 像原对象的别名                           |
| 常见语义 | 可选对象、数组遍历、底层接口 | 非空借用、参数和返回值                   |

在 64 位进程中普通对象指针通常为 8 字节，但不是 C++ 标准保证。优先用 `nullptr`，因为它有专门类型 `std::nullptr_t`，不会像宏 `NULL`/整数 0 那样在重载解析中误选整数版本。

- **野指针**：从未初始化、内容不确定的指针。
- **悬空指针/引用**：原对象生命周期已结束，但仍指向原位置。
- 释放后置空只能避免该指针再次误用，不能使其他别名自动失效；根本方案是明确所有权并使用 RAII。

## 3. 动态内存、智能指针与异常安全【高频】

### 3.1 `new/delete` 与 `malloc/free`

```text
new T(args...) = operator new 分配原始存储 + 在其中构造 T
delete p       = 调用 T 的析构函数 + operator delete 释放存储
```

`new` 自动按类型计算大小，通常失败时抛 `std::bad_alloc`；`malloc` 接收字节数、返回 `void*`，失败返回空指针，不构造对象。必须成对使用：

- `new` ↔ `delete`
- `new[]` ↔ `delete[]`
- `malloc/calloc/realloc` ↔ `free`

混用或数组形式不匹配是 UB。`delete p` 和 `free(p)` 都**不会把调用者的指针自动置为 `nullptr`**。`delete nullptr` 与 `free(nullptr)` 是安全的空操作。

placement new 可在指定的、已正确对齐的原始存储中构造对象；它通常不分配存储，需要显式管理对象析构和底层存储。

### 3.2 三种智能指针

- `std::unique_ptr<T>`：独占所有权，不可复制、可以移动，通常无额外运行时成本。默认首选。
- `std::shared_ptr<T>`：共享所有权。控制块通常保存强引用计数、弱引用计数、删除器和分配器；最后一个强引用销毁对象，弱引用也消失后才能释放控制块。
- `std::weak_ptr<T>`：只观察、不增加强计数。用 `lock()` 原子地尝试获得 `shared_ptr`，对象已销毁则得到空指针。

```cpp
struct Node {
    std::shared_ptr<Node> next;
    std::weak_ptr<Node> prev; // 打破双向强引用环
};
```

`shared_ptr` 的控制块计数可由多个线程安全地增减，但这不使所指对象线程安全；同一个 `shared_ptr` 实例被并发修改也需要同步或相应原子接口。

常见坑：

- 不要用同一个裸指针分别构造两个 `shared_ptr`，否则形成两个控制块并重复释放。
- 需要从成员函数安全获得自身共享所有权时使用 `std::enable_shared_from_this`，不要写 `shared_ptr<T>(this)`。
- `shared_ptr` 没有 `release()`；`unique_ptr` 才有。
- 优先 `make_unique/make_shared`：异常安全、代码简洁；`make_shared` 通常把对象和控制块一次分配，但只剩弱引用时对象存储所在的大块内存可能延迟归还。

### 3.3 Rule of Three/Five/Zero

手工管理资源的类若需要析构函数，通常还要考虑：

- Rule of Three：析构、拷贝构造、拷贝赋值。
- Rule of Five：再加移动构造、移动赋值。
- Rule of Zero：优先让 `vector/string/unique_ptr` 等成员管理资源，一个都不手写。

拷贝构造必须接收引用，典型签名是 `T(const T&)`；若按值接收，为构造形参本身又要调用拷贝构造，形成无限递归。赋值发生在已有对象上，拷贝构造则创建新对象。

异常安全常分为：不泄漏且对象仍有效的基本保证、操作失败时状态不变的强保证、绝不抛出的 nothrow 保证。析构函数通常不应抛异常，移动构造若能保证应标 `noexcept`，这样 `vector` 扩容更愿意移动而不是复制。

排查内存问题可在测试环境使用 AddressSanitizer/LeakSanitizer、Valgrind 或 Visual Studio 内存诊断工具；预防仍应以 RAII、明确所有权和避免裸 `new/delete` 为主。

## 4. 左值、右值、移动与完美转发【高频难点】

### 4.1 值类别

面试中可先简化：左值通常表示有身份、可重复定位的对象；右值通常表示临时值或可被移动的对象。更严格地说，表达式分为 glvalue 与 rvalue，并细分为 lvalue、xvalue、prvalue。

```cpp
std::string s = "abc";      // s 是左值
std::string t = s;          // 拷贝
std::string u = std::move(s); // 可调用移动构造
```

`std::move` **不移动任何东西**，它本质上是把表达式强制转换为右值引用，表示“允许从这个对象转移资源”。真正是否移动由随后选择的构造/赋值函数决定。被移动对象必须保持有效、可析构，但值通常未指定；可以重新赋值，不应依赖旧内容。

### 4.2 移动实现

资源类的移动构造通常“偷走”指针并把源对象置于可析构状态：

```cpp
Buffer(Buffer&& other) noexcept
    : data_(std::exchange(other.data_, nullptr)),
      size_(std::exchange(other.size_, 0)) {}
```

移动优化的是所有权转移，不是让基本类型变快。一个有名字的右值引用变量在表达式中仍是左值。

### 4.3 完美转发

当 `T&&` 中的 `T` 由模板推导得到时，它可能是 forwarding reference：传入左值则折叠为 `T&`，传入右值则保持 `T&&`。

```cpp
template<class F, class... Args>
decltype(auto) call(F&& f, Args&&... args) {
    return std::invoke(std::forward<F>(f),
                       std::forward<Args>(args)...);
}
```

`std::forward<T>` 按最初传入的值类别转发；`std::move` 无条件把参数视为可移动。引用折叠规则可记为：只要组合中出现 `&`，结果就是 `&`；只有 `&& + &&` 才是 `&&`。

## 5. 面向对象与虚函数【高频】

### 5.1 封装、继承、多态

- 封装隐藏不变量和实现，只暴露稳定接口。
- 继承表达“is-a”，可复用接口和实现，但会增加耦合；能用组合表达时常优先组合。
- 多态分为编译期多态（重载、模板）和运行期多态（虚函数）。

通过基类指针或引用调用虚函数时，常见 ABI 使用对象中的 vptr 找到 vtable，再间接调用实际动态类型对应的函数。虚表机制是主流实现，不是标准规定的具体布局。

```cpp
struct Base {
    virtual ~Base() = default;
    virtual void run() const = 0;
};
struct Derived final : Base {
    void run() const override { /*...*/ }
};
```

只要类可能被通过基类指针删除，基类析构函数就应为 `virtual`；否则是 UB，而不只是“少调用一次析构”。若不允许多态删除，可把析构函数设为受保护且非虚，并明确接口约束。

构造函数不能是虚函数，因为必须先确定要创建的完整对象类型和布局；析构函数可以且常应为虚函数。构造/析构期间调用虚函数只分派到当前正在构造/析构的层级，不会进入尚未构造或已经析构的派生部分。

纯虚函数用 `= 0` 声明，使类成为抽象类；纯虚函数**可以在类外提供定义**，但派生类若不完成所有纯虚接口仍是抽象类。

### 5.2 重载、重写与隐藏

- **重载 overload**：同一作用域同名函数参数列表不同，编译期选择；不能只靠返回类型区分。
- **重写 override**：派生类覆盖基类虚函数，签名必须匹配，可有协变返回类型；始终写 `override` 让编译器检查。
- **隐藏 name hiding**：派生类声明同名成员后，基类的同名重载集合可能全部被隐藏；可写 `using Base::func;` 引入。

### 5.3 构造、析构和初始化顺序

构造顺序是：虚基类 → 直接基类（按继承声明顺序）→ 成员（按**成员声明顺序**）→ 构造函数体；析构顺序相反。初始化列表的书写顺序不能改变成员构造顺序。

必须在初始化列表中直接初始化引用成员、`const` 成员和没有默认构造函数的成员。对类类型成员而言，在函数体赋值可能意味着“先默认构造，再赋值”，不如直接初始化。

### 5.4 多继承与对象切片

菱形继承会让最派生类含有两份共同基类子对象，造成数据重复和访问二义性；虚继承可使共同虚基类只保留一份，但对象布局和访问成本更复杂。

把派生对象按值赋给基类对象会发生**对象切片**，派生部分被丢弃。运行时多态应使用基类引用或指针。

## 6. 高频关键字与语言细节

### 6.1 `const`、`static`、`inline`、`volatile`

**`const`**：表达不能通过当前访问路径修改。`const` 成员函数中的 `this` 类似 `T const*`，不能修改普通成员或调用非 const 成员函数；`mutable` 成员例外。`const` 不等于线程安全：对象内部可能有 mutable 状态，多个相关变量也可能需要整体同步。

```cpp
const int* p;       // 指向 const int，不能通过 p 改值
int* const p2 = &x; // const 指针，不能改指向
```

**`static`**：命名空间作用域的 `static` 名字具有内部链接；函数内 static 具有静态存储期和局部作用域；类 static 数据成员属于类而非每个对象，static 成员函数没有 `this`。C++17 可用 `inline static` 在类内定义变量。

**`inline`**：现代意义首先是允许一个实体在多个翻译单元中具有相同定义，满足 ODR；它只是内联展开提示，编译器可忽略，也可在没有 `inline` 时自行展开。类内定义的函数隐式 inline，虚函数在动态类型可确定时也可能被去虚拟化并内联。

**`volatile`**：用于内存映射设备、信号处理等特殊访问，告诉实现某些读写是可观察的；它**不提供原子性、线程间同步或 happens-before**。多线程共享变量用 `std::atomic` 或锁。

### 6.2 `auto`、`decltype`、`explicit`

- `auto` 类似模板按值参数推导：通常去掉引用和顶层 `const`；`auto&` 保留引用，`const auto&` 可绑定临时量，`auto&&` 在推导上下文中可成为 forwarding reference。
- `decltype(expr)` 根据表达式形式和值类别推导；`decltype(x)` 与 `decltype((x))` 可能不同，后者若 `x` 是左值通常得到引用。
- `explicit` 阻止构造函数或转换函数参与不期望的隐式转换。它不只适用于单参数构造；C++11 起多参数构造可因默认参数或列表初始化成为转换候选，C++20 还有条件 `explicit`。

### 6.3 四种 C++ 转换

- `static_cast`：有明确语言关系的编译期转换；向下转型不做动态检查，类型不匹配时使用对象会出错。
- `dynamic_cast`：对多态层次做运行时检查；指针失败返回 `nullptr`，引用失败抛 `std::bad_cast`。
- `const_cast`：增删 cv 限定；若原对象本身确实是 const，去 const 后写入仍是 UB。
- `reinterpret_cast`：低层表示转换，可移植性差，应限制在确有协议/平台依据的边界代码中。

### 6.4 宏、类型别名和 C 接口

宏是预处理文本替换，无作用域和类型检查，函数式宏还可能重复求值：`MIN(i++, j)` 可能让 `i` 增加两次。优先用 `constexpr`、内联函数和模板。

`using Id = std::uint64_t;` 与 `typedef` 都创建类型别名，`using` 对模板别名更清晰；二者都可以在块作用域使用。`extern "C"` 指定 C 语言链接方式，主要解决函数名修饰/ABI 链接，不会把 C++ 代码变成 C，也不能让 C 直接理解重载、类和异常。

### 6.5 现代 C++ 版本速记

- **C++11**：`auto/decltype`、`nullptr`、范围 `for`、lambda、右值引用与移动、智能指针、可变参数模板、`constexpr`、`enum class`、标准线程与原子库。
- **C++14**：泛型 lambda、lambda 初始化捕获、`make_unique`、返回类型推导增强。
- **C++17**：结构化绑定、`if constexpr`、折叠表达式、类模板实参推导、inline 变量、`optional/variant/any/string_view`、`filesystem`。
- **C++20**：Concepts、Ranges、协程、Modules、`span`、三路比较、`jthread/stop_token` 和更多 constexpr 能力。

面试时不必机械背全，应挑项目真正使用过的特性，说明它解决的问题和一个例子。

## 7. 模板与泛型编程

模板是编译期代码生成与类型计算机制：函数模板通常能从实参推导类型；类模板传统上需显式给出参数，C++17 起部分场景可用 CTAD 类模板实参推导。

```cpp
template<class T>
T max_value(const T& a, const T& b) {
    return b < a ? a : b;
}
```

- **全特化**：为完整的一组模板实参提供专门实现。
- **偏特化**：为一类实参模式提供实现；类模板可偏特化，函数模板不能偏特化，通常改用重载。
- **type traits**：在编译期查询或转换类型，如 `is_integral_v<T>`、`remove_reference_t<T>`。
- **可变参数模板**：`template<class... Args>` 接受参数包，C++17 可用折叠表达式展开。
- **Concepts（C++20）**：直接表达模板约束，使接口和报错更清楚。

模板通常放在头文件，因为实例化点需要看到定义。优点是类型安全、可内联、零成本抽象；代价是编译时间、错误信息复杂和多种实例化可能导致代码膨胀。

## 8. STL 容器、迭代器与算法【高频补充】

### 8.1 容器选择

| 容器                  | 典型实现           | 关键复杂度                                  | 适用场景                        |
| --------------------- | ------------------ | ------------------------------------------- | ------------------------------- |
| `vector`            | 连续动态数组       | 随机访问 O(1)，尾插摊还 O(1)，中间插删 O(n) | 默认首选，缓存友好              |
| `deque`             | 分段连续的块与索引 | 两端插删 O(1)，随机访问 O(1)                | 频繁首尾操作                    |
| `list`              | 双向链表           | 已有迭代器处插删 O(1)，查找 O(n)            | 需要稳定节点/拼接；通常缓存较差 |
| `map/set`           | 通常红黑树         | 查找、插入、删除 O(log n)，有序             | 需要顺序、范围查询、稳定迭代器  |
| `unordered_map/set` | 哈希桶             | 平均 O(1)，最坏 O(n)，无序                  | 只需快速精确查找                |

`unordered_map` 不允许**等价键**重复，但不同键完全可以具有相同哈希值，容器会处理碰撞。哈希质量、负载因子和 rehash 会影响性能。

### 8.2 `vector` 扩容

`vector` 通常维护起始、已用末尾和容量末尾三个位置。`size()==capacity()` 再插入时会：

1. 申请更大的连续存储。
2. 移动或复制构造旧元素到新存储。
3. 构造新元素，销毁旧元素并释放旧存储。

增长倍率由实现决定，常见约 1.5 或 2，不是标准规定。几何增长使连续 `push_back` 的摊还复杂度为 O(1)。重新分配会使所有指针、引用、迭代器失效；未重新分配时，插入点及其后的迭代器也可能失效。已知规模时用 `reserve` 降低扩容次数。

`emplace_back(args...)` 在容器尾部直接用参数构造元素；`push_back(obj)` 接收现成对象并复制或移动。若本来已有对象，`push_back(std::move(obj))` 未必比 emplace 多一次操作；`emplace_back` **不保证总是更快**，还可能触发原本不明显的显式构造。

### 8.3 迭代器与失效

迭代器把算法与容器解耦。能力从输入/输出、前向、双向到随机访问逐步增强；算法只能使用迭代器提供的能力，例如 `std::sort` 要求随机访问，不能直接排序 `list`，后者提供成员 `sort`。

常见失效规则：

- `vector` 扩容使全部失效；中间插删使操作点及其后失效。
- `list` 插入通常不使其他迭代器失效，删除只使被删节点失效。
- `map` 插入通常不使已有迭代器失效，删除只影响被删元素。
- `unordered_map` rehash 使迭代器失效，但对元素的引用/指针通常仍有效；删除目标元素当然失效。

### 8.4 字符串与视图

优先用 `std::string` 管理字符串。`strlen` 运行时扫描到 `\0`，不含终止符；`sizeof(array)` 得到整个数组字节数，`sizeof(pointer)` 只得指针大小，且通常不求值表达式。

`std::string_view` 是不拥有数据的只读视图，避免复制，但底层字符串必须比 view 活得更久，否则悬空。`strcpy` 不检查目标容量；`strncpy` 也可能不补 `\0` 且语义容易误用，现代接口优先 `string`、`span` 或显式长度检查。

## 9. 编译、链接与 ABI

典型流水线：

```text
.cpp ─预处理→ 翻译单元 ─编译→ 汇编 ─汇编→ .o ─链接→ 可执行文件/库
```

- 预处理展开 `#include`、宏和条件编译。
- 编译进行词法、语法、语义分析、模板实例化和优化，生成汇编/中间代码。
- 汇编产生目标文件，其中含机器码、符号和重定位信息。
- 链接器解析跨文件符号、重定位地址并组合目标文件与库。

**静态库**的所需代码在链接时进入可执行文件：部署独立，但体积大，库更新通常要重新链接。**动态库**在装载时映射，多个进程可共享只读代码页，升级和部署更灵活，但存在版本/ABI 兼容和装载开销；并非“每次调用都重新链接”，常见 PLT/GOT 懒绑定也通常只在首次解析符号时发生。

常见错误：

- 编译错误：语法、类型检查、模板实例化失败。
- 链接错误：只声明未定义、重复定义、库顺序/符号不匹配。
- 运行错误：动态库缺失、ABI 不兼容、UB 等。

头文件应放声明、模板定义和允许多重定义的 inline 实体。违反 ODR（单一定义规则）可能链接失败，也可能形成难查的 UB。

大小端描述多字节对象的字节排列：小端把最低有效字节放低地址，大端相反；网络字节序通常是大端。协议和序列化应显式转换，不要依赖主机端序。

## 10. C++ 并发【高频补充】

### 10.1 线程生命周期

```cpp
std::thread t([] { do_work(); });
t.join(); // 等待完成
```

可 join 的 `std::thread` 在析构时会调用 `std::terminate`，所以必须 `join` 或 `detach`。`detach` 后难以管理任务、异常和所引用对象的生命周期，通常优先结构化地 join。C++20 `std::jthread` 析构时会请求停止并 join，更安全。

### 10.2 数据竞争与同步

两个线程执行冲突的内存访问，至少一个写、至少一个是非原子操作，且二者之间没有 happens-before，就构成 data race，程序行为未定义。常用工具：

- `std::mutex` + `std::lock_guard/unique_lock`：保护复合不变量。
- `std::scoped_lock`：一次按无死锁算法锁住多把锁。
- `std::condition_variable`：等待状态变化，使用 `while`/带谓词的 `wait`。
- `std::atomic<T>`：单变量原子操作和内存序；不自动保护多个变量组成的不变量。
- `std::shared_mutex`：读多写少时允许多读者。
- `std::future/promise/async`：传递一次性异步结果和异常。

```cpp
std::unique_lock lock(m);
cv.wait(lock, [] { return !queue.empty() || stopped; });
// wait 原子释放锁并睡眠，醒来重获锁并重查谓词
```

`volatile` 不能替代上述机制。原子操作默认顺序一致；放宽到 acquire/release 或 relaxed 可能提高性能，但必须能证明 happens-before 关系。

### 10.3 单例和观察者

线程安全的懒加载单例：

```cpp
class Service {
public:
    static Service& instance() {
        static Service s; // C++11 起初始化线程安全
        return s;
    }
    Service(const Service&) = delete;
    Service& operator=(const Service&) = delete;
private:
    Service() = default;
};
```

单例引入全局状态和测试耦合，不应因为“方便”就滥用。观察者模式让 Subject 保存订阅者并在状态变化时通知；用 `weak_ptr` 保存订阅关系可避免强引用环，但还需处理取消订阅、回调期间对象销毁和并发修改列表。

## 11. 高频面试速答

**Q1：`sizeof` 和 `strlen` 的区别？**

`sizeof` 是运算符，得到类型或对象表示所占字节数，结果类型为 `size_t`，通常编译期确定且不求值操作数；对指针只得到指针大小。`strlen` 是函数，要求有效的 `\0` 结尾字符序列，运行时逐字节扫描且结果不含 `\0`。

**Q2：为什么基类析构函数常设为 virtual？**

若通过基类指针 `delete` 派生对象，只有虚析构才能按动态类型先析构派生部分再析构基类；否则行为未定义。只要类用于多态，通常将析构设为 `virtual ~Base() = default`。

**Q3：`shared_ptr` 怎样解决循环引用？**

双方都用强引用会使强计数永不归零。把不代表所有权的一侧改成 `weak_ptr`，访问时 `lock()` 获取临时强引用；对象已销毁则返回空。

**Q4：`make_shared` 有什么优缺点？**

通常一次分配对象和控制块，局部性与异常安全较好。缺点是不能像单独构造 `shared_ptr` 那样直接指定自定义删除器，并且还有 `weak_ptr` 时整块分配可能不能立即归还。私有构造等场景也可能需要其他工厂写法。

**Q5：深拷贝和浅拷贝？**

浅拷贝逐成员复制；裸拥有指针会导致两个对象管理同一资源，可能重复释放。深拷贝为新对象复制独立资源。更现代的答案是用 `vector/string/unique_ptr/shared_ptr` 明确值语义或共享语义，遵循 Rule of Zero。

**Q6：`std::move` 后原对象还能用吗？**

能析构、能重新赋值，并满足该类型文档声明的操作；其值通常处于有效但未指定状态。`move` 只是转换，若类型没有移动操作甚至仍可能复制。

**Q7：`vector` 和 `list` 怎么选？**

默认优先 `vector`：连续内存、缓存友好、随机访问快，实际遍历和小规模插删常更快。只有确实需要稳定节点、已知位置 O(1) 插删或 splice，且能接受额外指针和缓存不友好时考虑 `list`。

**Q8：`map` 与 `unordered_map`？**

`map` 通常平衡树，操作 O(log n)，有序、支持范围查询，迭代器稳定性好；`unordered_map` 是哈希表，平均 O(1)、最坏 O(n)，无序，rehash 会使迭代器失效。选择取决于是否需要顺序、键的哈希质量、内存和稳定性。

**Q9：宏和 inline 函数？**

宏是无类型文本替换，可能重复求值且不遵守普通作用域；inline 函数是真函数，有类型检查、正常求值和调试语义。`inline` 不保证展开，它还承担 ODR 链接语义。

**Q10：`memcpy` 和 `memmove`？**

二者按字节复制。源和目标重叠时 `memcpy` 是 UB，`memmove` 保证得到仿佛先复制到临时数组的结果，常通过根据地址关系选择从前向后或从后向前复制实现。它们不应用来随意复制具有非平凡生命周期的 C++ 对象。

**Q11：四种 cast 怎样选？**

普通数值/已知层次转换用 `static_cast`；多态安全向下转型用 `dynamic_cast`；只改变 cv 限定用 `const_cast`；确实需要低层表示解释才用 `reinterpret_cast`。避免 C 风格转换，因为它隐藏实际采用的转换类别。

**Q12：对象初始化顺序？**

虚基类、直接基类、成员声明顺序、构造函数体；析构反向。初始化列表写的先后不会改变成员顺序，所以声明顺序和初始化列表最好保持一致。

**Q13：`push_back` 与 `emplace_back`？**

前者放入已有对象并复制/移动，后者转发构造参数在容器内直接构造。只有原本需要先创建临时对象时，emplace 才可能省一次移动；不是无条件更快。

**Q14：`const` 对象一定线程安全吗？**

不一定。`const` 只限制通过该接口修改普通成员；对象可能含 `mutable` 缓存、共享外部状态或内部指针。线程安全取决于同步和可见性协议。

**Q15：lambda 值捕获和引用捕获？**

值捕获在创建闭包对象时复制，默认 `operator()` 为 const，`mutable` 只允许修改闭包内副本；引用捕获访问外部对象，若闭包活得更久会悬空。异步任务中特别要谨慎捕获局部引用和 `this`。

**Q16：如何判断是编译错误还是链接错误？**

单个翻译单元中语法、类型、访问或模板实例化失败是编译错误；所有 `.o` 已生成，但符号找不到或重复定义是链接错误。程序启动后找不到动态库属于装载/运行期错误。
